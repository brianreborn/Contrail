# 1.0 Alpha Plan — Contrail

**Purpose**: Minimal first working build definition. Handoff target for the
private implementation repository.

**Status**: Locked from `REQUIREMENTS.md` as of 2026-09-05. Living; update
when requirements change.

## Definition

- **1.0 alpha** = desk that can watch a theater, stitch tracks, drive (or
  faithfully simulate) the X-app sequence for a dedicated account, and refuse
  to call a post done until that profile shows the tweet.
- Incomplete FR24 AccessibilityService coverage is **explicitly acceptable**.
  The companion APK is **1.0 beta**, and is what actually attaches to
  `com.twitter.android`.
- Alpha may use OpenSky ADS-B + a sandbox airlift injector so filters have
  something to follow without the Android overlay.

## Must-haves (hard)

1. FR24-shaped filters + Inland Empire theater.
2. Ident plate harvest. Not pixel trails off the globe.
3. Stitch by ICAO24.
4. Dedicated X vault: handle + login + password + “not my main” ack.
5. X session machine: switcher by handle → login-if-needed → composer →
   verify. Overlay shows handle/session, never the password.
6. Outbox, persist locally, never drop a draft.
7. Overlay chrome + kill. Kill aborts X login and skips posting.
8. Factual tweet under 280.

## Explicitly not required for alpha

- Android AccessibilityService companion (beta) — but the sequence it will
  run must already be specified and simulated on the desk.
- Sweep, KML, FR24 API, path-card media, Play Store, 24/7 worker, personal
  handles, 2FA/SSO automation.

## Handoff & scaffolding rules (REQ-P3)

- Do **not** create app source in this public repository.
- Private implementation repo is created **before or at** the first commit
  that builds toward the desk or APK.

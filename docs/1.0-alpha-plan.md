# 1.0 Alpha Plan — Contrail

**Purpose**: Minimal first working build definition. Handoff target for the
private implementation repository.

**Status**: Locked from `REQUIREMENTS.md` as of 2026-09-05. Living; update
when requirements change.

## Definition

- **1.0 alpha** = desk that can watch a theater, stitch tracks, auto-post from
  a dedicated X account, and prove the tweet landed.
- Incomplete FR24 AccessibilityService coverage is **explicitly acceptable**.
  The companion APK is **1.0 beta**.
- Alpha may use OpenSky ADS-B + a sandbox airlift injector so filters have
  something to follow without the Android overlay.

## Must-haves (hard)

1. **FR24-shaped filters** — callsign wildcard, aircraft, squawk, altitude
   band, category chips. Arm / disarm per rule.
2. **Theater** — Inland Empire default (KSBD / KONT / KRIV).
3. **Ident plate harvest** — lat, lon, alt ft, gs kt, track, squawk, ICAO24,
   registration. Not pixel trails off the globe.
4. **Stitch by ICAO24** — open on first match of an armed filter; sample while
   present; close on gone (~25s), explicit close, or kill.
5. **Dedicated X account gate** — four OAuth 1.0a user-context keys + checkbox
   “this is not my main account”. No ack / no keys → nothing leaves the
   outbox.
6. **Outbox** — queued / posting / posted / unverified / failed. Persist
   locally. Retry. Never drop a draft.
7. **Verify-on-land** — `POST /2/tweets` then `GET /2/tweets/:id`. Matching id
   required. If a tweet id exists, retry is lookup-only.
8. **Overlay chrome** — IDLE / ARMED / FOLLOW / RECORD, kill always visible,
   X ready vs X blocked, outbox count.
9. **Kill** — disarms every filter, closes open recordings, **skips posting**.
10. **Factual tweet** — ATC-style, under 280. Ident, type, route if known,
    FL / gs / duration, filter name, fix count, start→end lat/lon.

## Explicitly not required for alpha

- Android AccessibilityService companion (beta).
- Sweep mode (beta).
- KML / playback close-out (beta).
- Official FR24 API token (optional even in beta).
- Media upload of a path-card PNG (nice; text is enough).
- Play Store.
- Unattended 24/7 worker.
- Tweeting from a personal handle.
- Reimplementing FR24’s globe.

## Architecture sketch (what, not code)

1. **Desk (private web app)** — filters, library, compose, outbox, settings.
2. **Traffic source (alpha)** — OpenSky `states/all` bbox for the theater,
   merged with a local demo injector (Reach / heavies / 7700) so the sandbox
   always has a followable identity.
3. **Processing** — stitch loop keyed by ICAO24. Overlay is chrome only.
4. **Outbox processor** — armed only when the dedicated-account gate is
   satisfied. Interval retry. Max attempts then hold for a human Retry.
5. **X adapter** — OAuth 1.0a signing, create tweet, lookup tweet. Credentials
   passed per-request from localStorage; never stored server-side, never
   logged.
6. **Companion APK (beta, private)** — `AccessibilityService`, package-scoped
   to `com.flightradar24free`, overlay chrome, select → panel parse. Does not
   tweet.

## Handoff & scaffolding rules (REQ-P3)

- Do **not** create app source in this public repository.
- Private implementation repo is created **before or at** the first commit
  that builds toward the desk or APK.
- Public repo continues to hold requirements, plans, and research notes.
